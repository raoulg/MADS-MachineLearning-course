Kernels use the geometric structure of data

In space and in time, positions next to each other belong together: that is how the data hangs together.

neighbours belong together

In a series, the samples next to each other form the beat. In an image, the pixels next to each other form an edge.

Data has geometry: in a series the samples next to each other belong together, in an image the pixels next to each other. Flatten a 400 by 400 grid and a dense layer of the same size needs 160 thousand times 160 thousand weights, 25.6 billion, and on top of that it has thrown away which cells were neighbours. Aggregating tensors

The tensor is (B, S, D). Each row shows one slice: one example, one channel, the positions along S. A bracket is what one output reads.

Downsampling is nothing more than fewer positions on an axis. One input, three ways to treat it; a bracket above the input is what one output reads, in the same colour as that output. A kernel of three with stride 2 jumps two positions each time: its windows overlap by one, a zero is padded at the start, and eight positions give four. notebook 2.2

The vanishing gradient problem

another geometry

A kernel assumes space: neighbours belong together, wherever they are.
A state assumes order: what came just before tells you what you need now, a Markov assumption.

what it costs

Step by step: h10 waits for h9, so no parallel windows.
Vanishing gradients: beyond roughly 100 to 200 steps the start hardly reaches the gradient any more.

We need some type of memory to manage what the state needs to forget, and what it needs to remember.

A state is context carried along an ordered axis. At every step the same weights combine the new input with the state so far, and hand the result to the next step. It is another assumption about the data than a kernel makes, another geometry: a kernel assumes space, neighbours that belong together wherever they are; a state assumes order, that what came just before tells you what you need now. That is a Markov assumption. It costs two things. You compute step by step: step ten has to wait for step nine, where a kernel computes all its windows at once. And the gradient vanishes on the way back: what lies more than roughly 100 to 200 steps back hardly reaches the update, which is the red of x1 thinning out along h. The next part is how a gate controls that.

■ 03 — what does a skip buy at depth?

goal 2.1

notebook 2.2

The signal to correct the errors is lost

The gradient is the signal that makes the layers learn the correct weights. Without a skip layer, this signal is lost.

One backward pass on the same 256 beats, before training · the size of the gradient on each block's weights, on a log scale.

The gradient is how a layer learns: it says in which direction to change the weights. Going back from the loss to block one, the plain stack loses the signal at every block, and the first blocks get a gradient many orders of magnitude weaker than the last: they hardly learn. With a skip every block gets a gradient of about the same size.

■ 03 — what is a skip?

goal 2.1

notebook 2.2

Skip layers are used in every deep architecture

invented for images, taken over by every architecture

2015ResNet · images

2017Transformer · text
2019N-BEATS · series
lesson 1your head, skip=True

He, Zhang, Ren, Sun (2015). Deep Residual Learning for Image Recognition. arXiv:1512.03385

What a skip is: a route around a block whose output is added to the block's output. Because it is added, the shape must stay the same, and it does. The block now only has to learn a correction to its input; when it has nothing to add, it can learn to output almost zero and the input passes unchanged. That is why a deep stack with skips does not lose what a shallow one had. He and colleagues introduced it in 2015 to train image networks of 152 layers, and since then nearly every architecture has one: WaveNet for audio, every block of a transformer, N-BEATS for series, and the skip switch you searched in lesson 1. Where it pays most is in deep stacks; what the class's own runs show about that is for the class dashboard, not for this slide.

The second instrument. A gate is a multiplier between 0 and 1 for every element, computed by the network from its input with a sigmoid, which is why the values are never outside that range. First only the gate on the output of a block T of x, multiplied element by element by the gate. Where the gate is 1 the element passes, where it is 0 it is gone, and in between a fraction passes. The same layer, now along time. At every step the input x of that step is mixed into the state h with a gate: h is the gate times the new input plus one minus the gate times the old state. Move the slider from left to right and watch the state. Open for input, closed for state: the state is only ever the latest input, there is no memory. In a real network the gate is computed from the input and the state by the network itself.

The kernel and the gate side by side, because they are easy to confuse. The kernel scans: a window slides along the axis, looks at neighbours and uses the same weights everywhere; the axis can get shorter. The gate weighs: one multiplier per element, between zero and one, and nothing moves, so the shape stays exactly the same. Put a gate on a state and it decides, per element, how much of the new candidate to take and how much of the old state to pass on: forget or remember. And the skip at the start of this part is a parallel route with the gate fixed at 1, always open. ■ 03 — what does a gate decide?

goal 2.6

notebook 2.2

Squeeze-excite: a gate with a bottleneck

squeeze

Every 2D channel is aggregated into a single number.

excite

Through a bottleneck it can only keep what statistically goes together most often. A sigmoid turns it into values between 0 and 1.

Squeeze-excite is a gate on the channels of a convolutional layer, and each channel is a feature: a face, cat ears, fur, a left ear, a right ear. Squeeze pools away H and W, so every channel is one number: where is gone, how strong is left. Excite pushes those numbers through a narrow layer and back out, with a sigmoid at the end, and the result multiplies the channels. The narrowness is the point: it can only keep what usually goes together. How do you know that a person with cat ears is not a cat? The other features, a human face, turn the cat ears down. How do you know that I still have two ears under a hat? You fill in what is statistically plausible: one ear makes the other expected. That is what this block can do: it sees a left ear and no right ear, the squeeze loses where they were, and the excite brings both ears forward because that is what usually comes together.

Before any design, look at the data per class: twenty beats of each, laid over each other. The top row is one patient per class, the bottom row twenty beats drawn at random over many patients. Within one heart the beats of a class lie almost on top of each other; across hearts they spread. That spread is why the data is split by patient, and it is what a model has to see through. N is easy to see: the next R-peak arrives on time near the end of the window. V is easy too: wide, and with a shape of its own. S is the hard one. So ask the class: is S a shape of its own a model can learn, or is it mostly not N and not V? If it is the second, what in a design could say unlike a normal beat? The network only fits the residual

recap from MADS-DAV · part 4

You know the decomposition: series = trend + season + residual.

Built into an architecture, trend and season stay a parallel route; only the residual goes through the network.

notebook 2.3decomposition and N-BEATS

N-BEATS (Oreshkin et al., 2019) repeats this idea in stacked blocks: each block adds its forecast to the sum and removes what it explained from the input of the next. arXiv:1905.10437

A recap from MADS-DAV, part 4 of the recap page: a series is a trend plus a season plus what is left. Built into an architecture that becomes parallel routes. The series is split by a fixed rule into trend, season and residual. Trend and season do not need a network, so they run parallel to it, straight to the sum. Only the residual goes through the network. All routes are added up in the forecast. This is the idea behind N-BEATS, drawn conceptually: the real model stacks many such blocks, each block adds its forecast to the total and subtracts what it explained from the input of the block after it, and in its interpretable form the trend and the season come from a fixed basis, polynomials and sines, whose coefficients the network predicts.

■ 04 — what does a block assume about your data?

goal 2.7

notebook 2.1

Geometric deep learning: every block is a bet on geometry

kernel bets on locality

a pattern means the same wherever it occurs

pays: the shape of a beat, a texture

fails: what matters lies far apart

state bets on order

what came before changes what this means

pays: a rhythm across beats, a sentence

fails: long series: it forgets; or order means nothing, as in a set

trend + season bets on periodicity

the series repeats with a known period

pays: solar per day, sales per week

fails: no period, or the period drifts

Every block you have seen today assumes something about the data, and that assumption is a bet. A kernel bets on locality: a pattern means the same wherever it occurs, which pays on the shape of a heartbeat and fails when what matters lies far apart. A state bets on order: what came before changes the meaning, which pays on rhythm and fails on long series, where it forgets, or on data where order means nothing. A basis of trend and season bets on periodicity, which pays on solar power per day and fails when there is no period. This way of reasoning is geometric deep learning: grids, sequences, sets and graphs each come with their own geometry, and with their own bet (Bronstein et al. 2021, in the references).

your design script

# exercises/designs.py · one typed step per operation
beat  = Input("B S D", S=187, D=1)
local = Conv1D(beat, k=5,  out=16)    # (B,187,1) → (B,187,16)

x     = Concat([local, wide], on="C") # → (B,187,32)
x     = Skip(Gate(Block(x, hidden=64)))  # block 1: Linear, GELU, Linear
x     = Skip(Gate(Block(x, hidden=64)))  # block 2 → (B,187,32)
x     = Skip(Gate(Block(x, hidden=64)))  # block 3 → (B,187,32)
pooled = GlobalPool(x, over="S")      # → (B,32)
score = Linear(pooled, out=3)        # → (B,3) the classifier

A design script says what you intend and what every step does to the shape. Read it in atlas before you train anything.

The last step is the classifier: (B, 3), one score per class N, S and V for each beat.

the schema in atlas

How you design from today on. A design script has one typed step per operation, and each step says what it does to the shape. Atlas reads that script and draws the schema: the shape on every arrow, where the branches split, here into a narrow and a wide kernel, and where they join again, in the concat on the channel axis. Then three blocks, each a linear, a gelu and a linear, each with a gate and a skip around it, so every block can pass its input on untouched. A global pool over the sequence axis leaves one vector per beat, and the last Linear is the classifier: three scores per beat, one per class. Reading this picture is how you check a design before it costs you a training run, and how you explain it to someone else without your agent. Conv1D, Block and GlobalPool are names in a design script here; they arrive in vectormesh 0.14, so nothing on this slide claims they run today.

The majority classifier, your baseline, always says normal: 90% accuracy, and it finds no patient. A trained model finds seven of the ten at the price of six false alarms; look at precision and recall on the rare class, and at F1 to put them in one number.

The metric fits the problem, and the problem is imbalance. First only the dots: a classifier that always says normal is right ninety times out of a hundred. Press forward: it finds not one abnormal beat, so recall is zero and F1 is zero. Press forward again for the trained model, with its three misses, the false negatives, and its six false alarms, the false positives. Once more for the table. In the heartbeat data most beats are normal. Take a hundred beats, ninety normal and ten abnormal: the majority classifier, which always says normal and is the baseline to beat, is right ninety times and has an accuracy of 90 percent, and it finds not one abnormal beat. The trained model finds seven of ten, raises six false alarms, and has an accuracy of 91 percent, hardly better, while recall went from zero to 70 percent. Accuracy counts everything that is right, so the big class decides it. Precision asks: of the beats I flagged, how many were abnormal. Recall asks: of the abnormal beats, how many did I find. F1 is the harmonic mean of the two, so it is low when either is low. Which of them you care about depends on the cost: a missed patient costs a diagnosis, a false alarm a second look. The numbers here are illustrative; the real class balance is on the dataset card.

The close: the spine of the lesson, along the ranks of the tensor. A three-dimensional tensor, batch by sequence by dimensionality, is a series: there the kernel is a 1D conv, which torch wants as batch by dimensionality by sequence, so you permute first, and the trend-and-season basis, the stride and pool, the global pool and the state work on it. Each of them does something visible to the shape: a kernel without padding shortens the sequence a little, a stride or pool halves every axis it works on, a global pool leaves one slice of D, a state leaves one hidden vector. A four-dimensional tensor, batch by channels by height by width, is an image or a folded beat: there the kernel is a 2D conv, a patch that slides along two axes, and a stride or a pool shrinks both of them. Linear, gate and skip work on the last axis, whatever comes before it, so the red edge is the axis they use. A Linear usually goes from more features to fewer. A gate keeps the shape and turns some elements off, drawn in black. A skip keeps the shape and adds the correction the block learned, drawn in red. Next to each block is the bet it makes about your data. When you design today, every block in your design script has a place on this slide, and you should be able to say why its bet fits your data.
